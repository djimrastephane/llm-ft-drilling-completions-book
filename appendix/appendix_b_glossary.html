Appendix B: Drilling, Completions & Fine-Tuning Glossary

This glossary supports Chapter 2’s training-example builder and every later chapter’s “Engineering Translation” callouts. It is split into two parts: common oilfield shorthand you’ll see in raw report text, and the fine-tuning/ML vocabulary this book introduces gradually, gathered here for quick reference. Neither list is exhaustive — abbreviation usage varies by operator, rig contractor, and basin, and the ML terminology here is deliberately scoped to what this book actually uses.

B.2 Fine-tuning and local LLM vocabulary

Term Plain-language meaning
Base model The general-purpose model before any domain fine-tuning — Chapter 1’s starting point.
Fine-tuning Updating a model’s weights on your own data so it performs better on your specific task or domain.
LoRA (Low-Rank Adaptation) A parameter-efficient fine-tuning method that trains a small add-on to the model instead of every weight — Chapter 5’s technique.
QLoRA LoRA fine-tuning on a quantized (compressed) copy of the base model, cutting memory needs further.
Quantization Storing a model’s weights at lower numerical precision to shrink memory and speed up inference, at some accuracy cost.
Checkpoint A saved snapshot of a model’s weights at a point during training — Chapter 8.
Tokenizer The component that splits text into the sub-word units (“tokens”) a model actually processes — Chapter 4.
Instruction/response pair A single training example: an instruction (and optional input) paired with the desired output — Chapter 2’s core data format.
Epoch One full pass through the training dataset.
Perplexity A numeric measure of how well a model predicts held-out text; lower is generally better — Chapter 11.
Hallucination A fluent but factually unsupported model output — Chapter 10 covers detecting and mitigating it.
Drift A model’s behavior changing across versions or over time. A regression is drift for the worse – something that used to work stops working in a version meant to be an improvement — Chapter 12.
RAG (retrieval-augmented generation) Combining a model with a retrieval step over external documents, instead of relying only on what’s in its weights — Chapter 9.
Grounded / grounding An answer that’s actually built from a real, cited source, not just retrieved alongside it — Chapter 10 checks the difference.
Faithfulness How well an answer’s actual content matches what a specific source says — Chapter 10’s word-overlap check is one simple way to measure it.
Evaluation set A fixed, reusable list of questions with known-correct answers, held back from training — Chapter 11 builds a real one from the report Chapter 2 reserved.
Continuous fine-tuning Updating a model again as new data becomes available, instead of training it once and leaving it fixed — Chapter 13. Answers how to incorporate new data, not whether the result should replace what’s currently deployed; that’s still Chapter 12’s comparison, run again.
