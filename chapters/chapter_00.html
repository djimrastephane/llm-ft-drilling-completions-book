Part 0: Preparing Your Local LLM Workshop

Estimated time: 30–45 min  ·  Difficulty: 🟢 Beginner  ·  No prior programming experience assumed

Learning objectives

By the end of this chapter, you will be able to:

  • Install Python and confirm it works
  • Get a copy of this book’s companion repository onto your own machine
  • Create and activate a virtual environment for this book
  • Install this book’s dependencies
  • Check whether your machine has a GPU fine-tuning can use, and know what to expect if it doesn’t
  • Run setup_check.py and get a clean bill of health before Chapter 1

AI terms you’ll meet in this book

New vocabulary shows up gradually, one or two terms per chapter, each explained with an “Engineering Translation” callout the first time it matters. This page isn’t a substitute for those — it’s a quick-reference sheet to glance back at when a term from an earlier chapter resurfaces and you just want the short version, not the full explanation again. (Appendix B has the complete glossary, oilfield abbreviations included, if you need more than this.)

Term What it means here
Model The software that generates an answer from a question.
Base model The general-purpose model before any domain fine-tuning — Chapter 1’s starting point.
Fine-tuning Updating a model’s weights on your own examples so it performs better on your specific task.
Weights The model’s internal numbers that determine its behavior — what fine-tuning actually changes.
Token One piece of text after the model’s tokenizer cuts it up — sometimes a whole word, sometimes a fragment — Chapter 4.
Embedding A list of numbers standing in for a token or phrase, so the model can do math with meaning instead of letters — Chapter 4.
LoRA adapter A small, separate set of numbers trained instead of the full model, added on top of the frozen base weights — Chapter 5.
Rank How narrow LoRA’s two small adapter tables are — smaller is cheaper to train, at the cost of a rougher approximation — Chapter 5.
Training example One input and the answer you want the model to learn from — Chapter 2.
Epoch One full pass through the training data.
Loss A number measuring how wrong the model’s predictions were on one pass — should fall as training continues.
Checkpoint A saved snapshot of the model’s weights at one point in training — something to resume from if a run is interrupted — Chapter 8.
Held-out data Reports deliberately kept out of training so you have something honest to test on afterward — Chapter 2.
Inference Asking the trained model a question and getting an answer back, as opposed to training it.
Quantization Storing a model’s weights at lower numerical precision to shrink memory and speed up inference, at some accuracy cost.
Perplexity A numeric measure of how well a model predicts held-out text; lower is generally better — Chapter 11.

0.1 Why this chapter exists

Every chapter from here on assumes four things are already true: Python is installed, this repository is on your machine, a virtual environment for it is active, and this book’s packages are installed inside that environment. None of that is difficult, but skipping or rushing it is the single most common reason a reader gets stuck before Chapter 1 even starts — usually with a confusing error that has nothing to do with drilling, completions, or language models, and everything to do with one of these four things not being true yet.

This chapter does all four, one step at a time, with no assumption that you’ve done any of it before.

TipAlready comfortable with Python and virtual environments?

Skip the explanations in 0.2 (installing Python), 0.6 (hardware check), and 0.7 (choosing an editor) — you already know that part. You still need to actually do 0.3 (clone this repository), 0.4 (create this book’s own virtual environment), 0.5 (install its requirements), and 0.8 (run the setup check) like everyone else — they’re specific to this book, not to Python in general — but you can move through them fast. If 0.8 comes back clean, you’re done with this chapter.

0.2 Install Python

This book targets Python 3.11 or later — the same version pinned in requirements.txt and environment.yml.

TipEngineering Translation: what is Python, here?

Python is the programming language every script in this book is written in. Installing it is like installing the one piece of shop equipment every other tool in this book plugs into — nothing past this section runs without it.

macOS: Python 3 usually needs to be installed explicitly (the system’s built-in python3 is often older or missing entirely). Download the latest 3.11+ installer from python.org/downloads and run it, or if you have Homebrew installed:

brew install python@3.11

Windows: download the installer from python.org/downloads. On the first installer screen, check “Add python.exe to PATH” before clicking Install — this is the step almost everyone forgets, and it’s what Section 0.11 below assumes you didn’t.

Linux: most distributions ship Python 3, but check the version — it may be older than 3.11. On Ubuntu/Debian:

sudo apt update && sudo apt install python3 python3-venv python3-pip

Confirm it worked:

python3 --version

Expected output: something like Python 3.11.9 (any 3.11 or later patch version is fine). If you see command not found or a version below 3.11, revisit the install step for your platform above.

0.3 Clone this repository

If you’re comfortable with git:

git clone https://github.com/djimrastephane/llm-ft-drilling-completions-book.git
cd llm-ft-drilling-completions-book

Never used git before? Click the Download ZIP button on the repository’s GitHub page instead, unzip it, and open a terminal inside the unzipped folder.

Expected output: a folder named llm-ft-drilling-completions-book (or similar) containing, among other things, a book/ folder — everything from here on happens inside book/.

cd book

0.4 Create and activate a virtual environment

TipEngineering Translation: what is a virtual environment?

A virtual environment is a private, self-contained set of Python packages just for this project — like a dedicated toolbox for this book that doesn’t get mixed up with tools installed for anything else on your machine. Without it, this book’s packages (and their exact versions) could conflict with something else Python-related already on your system.

From inside book/:

python3 -m venv .venv

What just happened? This created a .venv folder holding a private copy of Python and an empty toolbox, specific to this project.

Now activate it — you’ll need to do this every time you open a new terminal window to work on this book:

source .venv/bin/activate          # macOS/Linux
.venv\Scripts\activate             # Windows (Command Prompt or PowerShell)

Expected result: your terminal prompt now starts with (.venv). That prefix is your confirmation the virtual environment is active — if it’s missing, the next step will install packages into the wrong place.

0.5 Install requirements

With (.venv) showing in your prompt and still inside book/:

pip install -r requirements.txt

What just happened? pip read the list of packages this book needs — transformers, torch, peft, and the rest — and installed them into your .venv. torch in particular is a large download (several hundred MB to a few GB depending on platform and whether a GPU build is selected), so this step can take a few minutes even on a fast connection. That’s normal.

Expected output: a long scroll of Downloading... and Installing collected packages... lines, ending with something like Successfully installed torch-... transformers-... peft-... ... and no red ERROR lines.

Notebitsandbytes and your platform

requirements.txt installs bitsandbytes (used for 4-/8-bit QLoRA fine-tuning) only on Linux — it has no working build for macOS. If you’re on macOS or a CPU-only machine, this is expected and not an error; Chapter 5 explains the full-precision LoRA path you’ll use instead.

0.6 Check your hardware

Fine-tuning, even the parameter-efficient kind this book uses, is more sensitive to your hardware than simply running a model is. This section doesn’t require you to buy anything — it just sets expectations for later chapters.

import torch

if torch.cuda.is_available():
    print(f"CUDA GPU available: {torch.cuda.get_device_name(0)}")
elif torch.backends.mps.is_available():
    print("Apple Silicon MPS device available")
else:
    print("No GPU detected -- CPU-only.")

What just happened? This checks for three possibilities: an NVIDIA GPU (cuda), an Apple Silicon Mac’s built-in accelerator (mps), or neither.

What this means for you:

  • CUDA GPU: the most comfortable path. Chapter 5’s fine-tune, and the heavier Part II chapters, will run in minutes.
  • Apple Silicon MPS: works well for this book’s small models, though somewhat slower than a dedicated CUDA GPU.
  • CPU-only: every chapter is still designed to run — you’ll use a smaller model and fewer training steps where a chapter calls for it, at the cost of longer wait times, not a dead end.

0.11 Troubleshooting

Symptom Likely cause
command not found: python3 (Windows) Python wasn’t added to PATH during install — re-run the installer and check “Add python.exe to PATH” (Section 0.2).
python3 --version shows a version below 3.11 You have an older Python 3 install alongside a newer one; try python3.11 --version explicitly, or reinstall from python.org.
Prompt never shows (.venv) after activating Confirm you ran the activate command from inside book/, and that .venv/ actually exists there (Section 0.4).
pip install -r requirements.txt fails partway through Re-run the same command — a partial download is the most common cause and simply retrying often finishes the job. If it fails on torch specifically, try pip install torch alone first, then re-run pip install -r requirements.txt.
setup_check.py reports [FAIL] <package> not importable (.venv) isn’t active, or pip install -r requirements.txt didn’t finish successfully — re-check Sections 0.4 and 0.5.
ModuleNotFoundError: No module named 'torch.backends' when checking hardware Your torch install didn’t complete — re-run pip install -r requirements.txt and check for ERROR lines.
